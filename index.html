Data Warehouse & Mart Build: End-to-End ETL Pipeline

Purpose
Transform raw job-posting CSVs from Google Cloud Storage into a normalized star-schema warehouse, then create specialized analytical marts for fast, focused questions.
Architecture
A DuckDB pipeline moves from extraction and loading into company_dim, skills_dim, job_postings_fact and bridge tables, then branches into flat, skills and priority marts.
Technical evidence
Wrote explicit table-creation and loading scripts, defined the grain of the fact table, used explicit data types and record-count checks, and kept reruns safe with DROP TABLE IF EXISTS.
SQL techniques
Uses CTEs, DATE_TRUNC, EXTRACT, STRING_AGG, explicit column mapping and MERGE-based incremental updates for the priority mart.
Tools
DuckDB with httpfs, SQL, Google Cloud Storage, VS Code, Terminal, Git and GitHub
Outcome
A single source of truth for analytical queries plus marts optimized for ad-hoc exploration, skill-demand time series and priority-role tracking.

Automated Sales ETL Pipeline

Purpose
Show the complete path from messy input data to a queryable analytical result, in a small project that is easy to check by hand.
Pipeline
Extract the raw CSV with pandas, Transform it (missing customer names become “Unknown”, order status is trimmed and capitalised, and Total_Amount = Quantity × Price_Per_Unit), Load it into a SQLite table called cleaned_sales, then Analyze with a SQL GROUP BY on status.
Verified output
On the sample data it reports 1 cancelled order (1,600), 2 delivered (1,750), 1 pending (900) and 1 shipped (1,200).
Tools
Python, pandas, SQLite, SQL
Scope
A deliberately small build on 5 sample records, made to learn the ETL pattern end to end. Re-running it replaces the table, so results stay reproducible.
